- **Hypotheses / what we're testing:** Exploratory: what does the NLA read at the token positions where the model **commits to its final answer** (the `Output:` / `Lines: [...]` line)? Prompted by user review of the gallery — the model's replies were visible, the NLA's view wasn't front-and-center.
- **Setup:** Same rig as the parent entry (nla-mi; AV server GPU 1, extractor+AR GPU 0, temp 0). New script [`../../nla/src/answer_reads.py`](../../nla/src/answer_reads.py): locates the answer line in each stored reply, reads up to 3 token positions on it, appends `answer_reads` to `captures.json`, and **rebuilds `EXAMPLES.md`** — full untruncated reads as blockquotes (the old 260-char table cells were unreadable), answer-line reads in their own highlighted section directly under the model answer. 12 new reads (fibfib has no answer line — truncated run, marked as such).
- **Results:** (gallery: [`../../data/nla/examples/EXAMPLES.md`](../../data/nla/examples/EXAMPLES.md))
  - **The NLA reliably reads the *act* of answering:** every answer-line read describes a concluding summary being emitted in the required format — "completing the answer with 'Output: the final answer'", "Lines … mirrors the prompt's concluding question format", "signals a closing box". The functional state (finalizing a formatted list/output answer) is read exactly.
  - **The specific values are lossy/confabulated variants:** JS/58 (true `[2,3,4]`) reads "the final output … `[1, 2, 3]`, the sorted result"; slice_1 (model `[1,3,5]`) reads "Lines 2, 3, 4 are active" / "order: 3, 2, 1"; slice_2 (model `[2,5,7]`) reads "indices 3, 5, 7" — *partially echoing the model's actual (wrong) answer*; slice_3 reads "Lines 1-10" / "rows 1,2 / 3,5". Numeric content is approximately right in shape, unreliable digit-for-digit.
  - Round-trip cos on answer-line reads 0.77–0.92; CJK 0/12.
- **What worked / hypothesis verdict:** N/A (exploratory). Clean characterization: **theme/format exact, digits approximate** — the known "trust theme, not specifics" NLA property, now demonstrated at answer-commitment positions on code tasks.
- **Observations:** For N1 this calibrates the agreement metric: comparing NLA reads against CoT *content/theme* is supported; expecting digit-exact answer readout from single reads is not (FVE≈0.75 channel). The slice_2 read echoing the model's wrong answer ("3, 5, 7" ~ model's [2,5,7]) rather than the truth is exactly the faithful-to-the-computation (not to the world) behavior the instrument should have.
- **New questions / new hypotheses:** Would aggregating several answer-line reads (or reading a few positions earlier, where the answer is being *decided* rather than *formatted*) recover digits more reliably? Does the decided-vs-formatted distinction matter for N1's window placement?
