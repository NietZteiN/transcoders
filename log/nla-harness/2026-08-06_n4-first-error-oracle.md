### Target Date: 2026-08-06 (N4 — first-error oracle: built, gated, coverage below target)
- **Hypotheses / what we're testing:** None — N4 is an *instrument*, not a hypothesis. Its validity claim is a gate: can we mechanically locate where a wrong reasoning trace first diverges from ground truth? Success = the flagship known-answer tests pass and coverage clears the pre-set bar.
- **Setup:** CPU only, no GPU, no server. New modules: [`../../nla/src/capture_core.py`](../../nla/src/capture_core.py) (S0 refactor), [`../../nla/src/claims.py`](../../nla/src/claims.py), [`../../nla/src/exec_oracle.py`](../../nla/src/exec_oracle.py), [`../../nla/src/first_error.py`](../../nla/src/first_error.py). Input: the 117 non-truncated wrong cases of the 2026-08-04 corpus. Output: `data/nla/n4/2026-08-06/first_errors.jsonl`. Seed 20260724.
- **Results:**
  - **S0 gate PASSED:** `align_reply()` reproduces **804/804** banked anchor spans exactly, so N5's positions will be directly comparable to the 5,090 banked reads. This was the whole point of factoring the arithmetic out rather than copying it.
  - **Known-answer gate PASSED** (all four, matching the pre-planning trial exactly):
    `63:L1b` → `smoothArea(4)` claimed 1, truth 2 @77% · `63:L1` → `fibfib(4)` claimed 1, truth 2 @77% ·
    `63:L3` → `fibfib(5)` claimed 3, truth 4 @84% · `63:L2` → **no value error** (correctly falls through to D3).
  - **Coverage gate FAILED: 41/117 localized (35%), against a ≥60 bar.** Breakdown: D0 slice set-diff **20/20**, D2-call **3**, D2-state **18**, D1 **0**, unlocalized **76**.
  - **D1 confirmed useless on this corpus: 0/140 traces contain an internally false arithmetic claim.** The model's arithmetic is always self-consistent; it computes the wrong thing. Kept in the code for other corpora, but it contributes nothing here.
  - **Why the gate missed:** the ≥60 bar was derived from *claim presence* (85% of cases carry ≥3 checkable claims). Claim presence ≠ checkability. Only **26/117** cases had any claim actually checked, because ground truth must be *observable*: Python locals/containers are (ast instrumentation), **JavaScript locals are not** — JS has no assignment hook, and the argument-array Proxy only sees containers passed in. JS localization is 4/47 vs Python 17/50.
  - **Example of a real, non-flagship localization:** `cruxeval-x-python/106:L1` @51% — trace claims `var_ece6` becomes `[4, 4, 16, 2, 8, …]`, true state `[4, 4, 4, 2, 8, …]`: it read `nums[2]` as 8 when the value there was 2. Exactly the failure shape predicted during planning.
  - **Position:** the three high-confidence (D2-call, conf 0.90) errors sit at **77/77/84%** of the trace; the lower-confidence D2-state set has median 43%. The late clustering is a property of the recurrence family, not of errors in general.

- **Observations — five bugs found by running it on real data, none of which unit tests would have caught:**
  1. **Sandbox killed node**: `RLIMIT_AS` 2 GB crashes V8 at startup (it reserves a huge virtual space); `RLIMIT_NPROC` counts *all* 96 of the user's processes, so no workable value exists. Now 12 GB AS + wall-clock timeout as the real containment.
  2. **Hex literals**: `fibfib(2) = 0x1` parsed as 0 (the L1 tier renders everything in hex).
  3. **Chained equalities**: `f(3) = \`1+0+0\` = 1` — the value is after the *second* `=`.
  4. **`enriched.json` drops `meta`**, so `fn_name` was unavailable; entry points now derived from the call string.
  5. **Instrumentation blind spots**: the first version recorded only explicit `Assign`, missing **loop variables** and **in-place mutations** (`nums.insert(...)`) — on the corpus's dominant shape the only assignment is `count = len(nums)`. Adding those took localization 31→41. Also fixed: tuple/list equivalence after the JSON round-trip (`[(4,1)]` vs `[[4,1]]` was a false positive), and initial-container-state recording (the model's first claim is the *input* state, the tracer's first event was post-mutation → off-by-one).
