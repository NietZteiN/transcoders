# 2026-08-15 — N13: no internal signal tracks *torn-ness*; read instability turns out to be describability measured twice (r = −0.96)

**Goal / hypothesis.** Exploratory (no pre-registration; deliberately **not** added to the
{HT12, HT13, HT14} BH-FDR family). The question: can `rt_cos` — or any other measurable
quantity — signal **confusion** in the specific sense of the model entertaining two incompatible
readings at once, the way a person reading *"a plus b squared"* is split between `a + b²` and
`(a+b)²`?

This is **not** HT12. HT12 asked whether `rt_cos` predicts *correctness* and refuted it
(length-matched β = −0.00022, CI [−0.0051, +0.0047], p = .93). But `correct = False` merges two
opposite internal states — **confidently wrong** (one reading, firmly held, mistaken) and **torn**
(two readings, unresolved). Nothing in the programme could see the difference, because every
banked capture is a **single greedy run**. Predictions: (1) `rt_cos` does nothing here — it is a
length-and-describability meter; (2) `act_norm`, never tested against any outcome, is unknown;
(3) **read instability** — verbalizing the *same vector* K times at T > 0 — is the one measure
whose construction matches the phenomenon, and the most likely to work.

**Setup.** Four stages, run back-to-back unattended on **one GPU (id 1)**, seed **20260724**,
Qwen2.5-7B-Instruct L20. Autopilot `nla/scripts/n13_autopilot.sh` (session leader, `sid == pid`,
`tty = ?`, so logoff-immune); stages 19:11→21:19 local, **0 errors in all four**.

| stage | what | scale | time |
|---|---|---|---|
| 1 `answer_entropy.py` | K=8 sampled answers @ T=0.8, top_p .95 | 330 graded items, 2,640 gens | 1.48 h |
| 2 `recover_act_norm.py` | forward-pass-only norm recovery | 380 cases, **5,090/5,090** positions | 64 s |
| 3 `read_instability.py` | K=5 verbalizations @ T=0.7 per vector | 400 positions, **2,000 reads** | 2.10 h |
| 4 `src/analysis/n13_torn.py` | horse race + 2×2 + class contrasts | CPU | seconds |

Corpus: the banked overnight set (`enriched.json`, 5,090 reads / 380 cases). Prompt, task list
and grader **imported verbatim** from `overnight_capture` rather than re-derived.

**Verification gates — all passed before any result was read.**
- Greedy regeneration reproduced the banked `model_answer` **8/8**.
- Re-extracted tokens matched the banked `anchor.tok` **5,090/5,090** (`token_identity_frac` 1.0),
  **0** positions dropped out of range, **0** norm outliers, norm median 109.7 (p05–p95 91.7–125.6,
  inside the documented ~100–170 band).
- Stage-3 floor gate passed on both measures (below) before Stage 4 was interpreted.

**Results.**

*Gate 1a — PASS.* Entropy has spread: 18.8% of items perfectly consistent (rule: stop at ≥80%),
mean entropy 0.433.

*Gate 1b — NULL.* The L1b trap does **not** raise answer entropy over length-matched L0:
**−0.0005, CI [−0.0815, +0.0816]** (n = 54 pairs). An interim n = 19 read +0.103 and reversed at
full n — the same interim-reverses pattern that bit B4.

*Behavioural anchor.* Answer entropy separates wrong from right at **AUC 0.843** (mean 0.672 vs
0.296). The "confidently wrong" state is real but **rare**: 6/120 wrong items are perfectly
consistent vs 56/210 right items. Being wrong and being unstable nearly coincide here, so the 2×2
is necessarily a *relative* contrast (modal share ≤ 0.25 vs ≥ 0.5).

*The horse race* — entropy ~ log reply length, then each internal signal (permutation null,
1,000 shuffles; n = 194 with complete coverage):

| added | R² | ΔR² | coef [95% CI] | p_perm | beats length? |
|---|---|---|---|---|---|
| `log_reply` | 0.3511 | 0.3511 | 0.360 [0.303, 0.421] | .001 | **yes** |
| `mean_rt_cos` | 0.3537 | 0.0026 | −1.07 [−3.52, +1.51] | .402 | no |
| `mean_act_norm` | 0.3537 | 0.0000 | −0.0002 [−0.016, +0.017] | .983 | no |
| `mean_instability` | 0.3703 | 0.0166 | +3.61 [0.15, 7.69] | **.029** | marginal |

*The 2×2 — torn vs committed-wrong, length-matched* (confound AUC **0.512**, so matching held):

| metric | AUC | CI 95% | torn | committed | n pairs |
|---|---|---|---|---|---|

| `instability` | 0.408 | [0.184, 0.644] | 0.0241 | 0.0264 | 14 |

AR-space cosine spans only ~0.971–0.994 (the AR-clustering caveat) while lexical Jaccard has ~15×

- **Floor gate — PASS on both measures.** `adversarial` is less stable than the `fn_orig` floor:
  AR +0.0109 [0.0065, 0.0153]; lexical +0.0243 [0.0094, 0.0388]. So the measure is *not* pure
  decoder stochasticity — it discriminates. (Case-clustered bootstrap throughout.)
- **Superposition vs emptiness — NULL on both.** `adversarial` − `l1_neutral` =
  **−0.0017 [−0.0059, +0.0025]** (AR) and **−0.0010 [−0.0133, +0.0120]** (lexical). Both include
  zero, and the point estimate is *negative*: vacant gibberish names are, if anything, marginally
  **more** unstable than decoys.

**Verdict — NULL, with a positive characterization. No internal signal at layer 20 tracks
torn-ness, because all three candidates are measuring the same thing: describability.**

The decisive number is the correlation between read instability and the banked `rt_cos`:
**r = −0.757 per read (n = 400), r = −0.958 at class level.** Read instability is not a new
instrument — it is describability measured a second way, inverted. A vector that is hard to
describe also gets described *inconsistently*.

That one fact explains every other result coherently:
1. **Why the floor gate passes** — `fn_orig` is the most describable class in the corpus, so it is
   both highest `rt_cos` (0.934) and lowest instability (0.0116). The gate confirms the measure
   works; it does not show that it measures ambiguity.
2. **Why superposition vs emptiness is null** — `l1_neutral` (0.8519) and `adversarial` (0.8749)
   have nearly the same describability, so nearly the same instability. The decoy injects
   *confident wrong* semantics, as describable as the truth; it does not install a second reading
   the verbalizer can waver between.
3. **Why instability squeaks past in the horse race while `rt_cos` does not** — it is a
   better-estimated version of the same quantity (5 samples vs 1). ΔR² = 0.017 over length, and
   it **fails the 2×2**, the one test that isolates torn-ness by holding correctness fixed. Read
   as a describability estimate that inherits entropy's correlation with difficulty, not as a
   torn-ness detector.
4. **Length still dominates.** `log_reply` alone explains **35%** of answer-entropy variance;
   everything internal fights over the remaining ~2%. Consistent with `rt_cos`'s +0.277 read-length
   correlation and with instability's −0.479 correlation with sampled read length.

**The original question is therefore answered.** Faithfulness is not lower on code the model finds
confusing; it is lower where there is *less to say*, and length is the dominant factor. The
describability account survives a direct test designed to break it.

**Bugs / process notes (all caught before results were read).**
- **Wrong read corpus.** Stage 2 was first written against `n7/keys.jsonl`, which looks
  interchangeable with `enriched.json` but shares only **232 of ~5,000** (case, position) pairs.
  The Stage-4 join would have silently collapsed to that overlap.
- **Invalid significance test.** The horse race originally bootstrapped ΔR² and asked whether the
  CI excluded zero. ΔR² is **non-negative by construction**, so that CI essentially always
  excludes zero — on synthetic data with three predictors known to be pure noise, all three were
  reported "significant". Replaced with a permutation null plus a coefficient CI (free to contain
  zero); the same synthetic data then returned p = .51–.58 for all three. **This bug would have
  produced a false positive as the headline result.**
- **Empty analysis cell.** "Confidently wrong" defined as 8/8 identical answers is unreachable at
  T = 0.8 (0/43 wrong items). Thresholds made relative; the emptiness is itself reported.
- **Throughput.** AR on CPU ran Stage 3 at 4.3 reads/min (7.7 h); `NLACritic.score()` re-runs
  `reconstruct()` internally, so it was being paid twice per read. Deduped, and the subject model
  is freed after phase A (`torch still holds 0.0 GB`) so AR fits on the same card: **16.0
  reads/min**.
- **Autonomy.** Added a consecutive-failure abort (tested against a dead AV port — stops at 10,
  resumable) so a dead server cannot burn the 6 h wall budget writing error rows; added Stage 4 to
  the autopilot, which would otherwise have finished leaving inputs and no analysis.
- 91 unit tests pass (26 new in `nla/tests/test_n13.py`), including regression tests for the ΔR²
  bug and for case-clustered (not read-clustered) bootstrapping.

**Limitations.** One model, one layer (20), one temperature pair (T=0.8 answers / T=0.7 reads).
Instability averages only **~1.9 positions per item**, so the item-level term is underpowered —
the read-level class contrasts (n = 400 over 210 cases) are the well-powered tests, and the 2×2
instability cell rests on **14 pairs**. `fn_orig` is confounded with tier (it spans L0/L1/L2/L3
while `adversarial` is L1b/L3 only) and with token form (whole words vs bracket-glued fragments),
which is why interpretive weight sat on the form-matched `adversarial` vs `l1_neutral` pair. The
AR-space scale is compressed (0.971–0.994); the lexical measure agreed on every contrast, which is
what makes the conclusions credible rather than an artifact of AR geometry. `p_perm = .029` for
instability is uncorrected and would not survive multiplicity adjustment across the contrasts run
here.

**Next steps.** (1) Torn-ness may be real but not *linearly localized* at layer 20 — a layer sweep
is the obvious next probe, and it is cheap for `act_norm`/instability since no training is
involved. (2) The one robust positive here is behavioural, not internal: **answer entropy predicts
correctness at AUC 0.843**, which is the self-consistency result, obtained free as a by-product.
It is a better correctness signal than anything the NLA instrument provides and should be the
baseline any future internal signal must beat. (3) If torn-ness is to be studied at all, it needs a
manipulation that *induces* it — Gate 1b shows adversarial renaming does not — e.g. genuinely
ambiguous programs with two defensible outputs, rather than programs with one answer and a
misleading name.
