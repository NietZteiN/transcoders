### Target Date: 2026-09-13 (H-A10a pre-registration — can DEPLOYABLE features predict which items the write helps? The cheap half, no GPU)

- **Why this exists:** H-A8 ([`2026-09-13_budget-confound-results.md`](2026-09-13_budget-confound-results.md)) found that at a fair budget `c3_band` fixes **3 of 7** flippable items and breaks **0**, while breaking **6 of 53** non-flippable (5 of them already correct) — pooled exactly **0.0000**. The write works where the decoy did damage. But `flippable` is defined as *L0 correct ∧ L1b wrong*, i.e. from the ground-truth answer, so **targeting on it is oracle targeting**. The whole remaining gap between that structure and a deployable claim is a **selector** computable from the obfuscated code alone.
- **Correction recorded before any data:** an earlier session note of mine said Instrument 1's `A_id`/`A_struct` and Instrument 2's ISF were "already banked" as selector candidates for this item set. **They are not** — no attention or ISF measure exists for these 60 items. The banked `data/nla/n13/answer_entropy.jsonl` does cover all 60 snippet_ids, but it was produced on **Qwen2.5-7B-Instruct** (`answer_entropy_manifest.json`), which is both a model this project no longer runs and, decisively, **the wrong host**: flippability is a property of *Gemma-3-4B-it* getting L0 right and L1b wrong, so another model's entropy cannot select for it. Self-consistency on the obfuscated prompt for *this* host is therefore **not banked** and costs ~2–3 GPU-h (H-A10b, not this entry).
- **Deployability rule, frozen (this is the entry's real content).** A feature is admissible only if it can be computed from **the obfuscated code plus the trained AV**, never from `h0`, the L0 prompt, the L0 reply, or the truth. This rules out most of what is banked and is worth stating explicitly, because the tempting features are all inadmissible: `dG_S_swap/c3/edit/foreign/rt` all score the logp of the **L0 reply** (needs the clean run); `cos_delta_E` and `‖Δ_s‖` need `h0`; `noop_rate` needs the truth. **Admissible set (7 features):** `n_spans`, `n_editable`, `frac_editable`, `sum_n_edits` (all from the AV read on `h1b`), `l1b_prompt_len`, `noop_greedy_parsed`, `noop_parsed_rate` (a parse rate, no truth).
- **Hypotheses:**
  - **H-A10a-1:** does any admissible feature predict **`flippable`** (7 positives / 60)?
  - **H-A10a-2:** does any admissible feature predict **`harmed`** = `noop` correct ∧ `c3_band` wrong at the corrected 2 600-token budget (6 positives / 60)? A deployable *gate* needs both halves: steer where it helps, withhold where it harms.
  - **Method (frozen):** per feature, leave-one-out cross-validated logistic regression → LOO AUC. Null: **10 000 label permutations**, p = the permuted fraction reaching the observed AUC. **BH-FDR across all 7 × 2 = 14 tests.** Seed 20260724.
  - **Verdicts:** **`SELECTOR-CHEAP-FOUND`** if any feature reaches **AUC ≥ 0.70** with BH-q < 0.05 on either target · **`SELECTOR-CHEAP-ABSENT`** otherwise, which **licenses H-A10b** (the entropy run) rather than closing the question.
  - **Power, stated up front:** with 7 and 6 positives this can only detect a *large* effect; `SELECTOR-CHEAP-ABSENT` will be evidence that cheap structural features are insufficient, **not** that no selector exists. That asymmetry is the reason to run the free half first.
  - **Prediction:** `SELECTOR-CHEAP-ABSENT` on both targets, with `noop_parsed_rate` the most likely single hit if any (H-A8 showed non-answering is the dominant failure and it is answer-free). Confidence moderate — my record today is 2 hits in 6, and both hits rested on already-measured quantities, which this prediction does not.
