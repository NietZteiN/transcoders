### Target Date: 2026-09-13 (H-E14 pre-registration — the "training-free" erasure vector is not ORACLE-free, and the memo overstates it)

- **Claim precision first (this is a correction I am raising against my own headline result).** `nla_erasure.py:targets()` builds every erasure arm as `erase_target(h1b, dn, direction, alpha)` with **`dn = ‖h0_s − h1b_s‖` computed per span from the clean-state activation `h0`**. So the vector that "matches the trained NLA edit with no autoencoder and no training" ([`2026-09-13_erasure-vector-results.md`](2026-09-13_erasure-vector-results.md)) is training-free but **borrows the true per-span displacement magnitude at inference**, which the trained AV/AR never sees — the pair gets only the L1b prompt. The *direction* is honestly leave-one-out; the *magnitude* is an oracle. **This does not touch any directional verdict** (H-E3, H-E7c, H-E8 all compare arms that share the same `dn`, so the oracle cancels), but it does weaken the comparison the memo leans on — "the free baseline any such method must clear" is not deployable as stated, because a deployed method has no `h0`. Per CLAUDE.md §6 this correction goes in a new dated entry rather than an edit to the old one, and the published memo gets the caveat immediately.
- **Sizing, free (no GPU), from the banked vectors:** `‖Δ_s‖` CV is **0.306** at 4B L7, **0.526** at 4B L13, **0.179** at 12B L32; a leave-one-item-out mean norm mispredicts the true per-span norm by a median **0.185 / 0.410 / 0.115** respectively (p90 0.400 / 0.929 / 0.267). Whether that matters depends on how flat the α ladder is at each site, and the ladders differ sharply: 4B L7 is a **plateau** (α 0.5/1.0/2.0 → +28.51/+35.75/+36.96), 4B L13 **turns over hard** (+28.53/+32.61/**+11.02**), 12B L32 is **monotone** (+5.53/+8.60/+16.49).
