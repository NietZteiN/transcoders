Can we tell when a model is confused?

We built a way to measure whether a language model is torn between two readings of a program — then tested three internal signals against it. All three came back empty, for one reason we did not see coming.

The question came from an ordinary observation: a person reading the phrase “a plus b squared” genuinely cannot tell whether it means a + b² or (a+b)². They hold both at once. We wanted to know whether a language model ever does the same thing, and whether anything measurable inside it would show us.

The answer is no — not with any instrument we have. But the reason is more useful than the result, so this report is written to be readable with no prior context.

1 · What we are working with

Making a neural network’s internal state readable

A language model pushes text through roughly 28 stacked layers. At every layer, each word position holds a vector of 3,584 numbers — the residual stream. That vector is the model’s working state at that moment, and on its own it is unreadable.

A Natural Language Autoencoder is a pair of small trained models that turn it into English:

  • The verbalizer takes one vector and returns a sentence describing it.
  • The reconstructor takes a sentence and returns a vector.

Because it runs both ways, the description can be checked. Take a vector, describe it, turn the description back into a vector, and measure how close that is to the original. That number is the instrument’s faithfulness: how much of the state survived the trip through English. Everything here uses released, frozen checkpoints. Nothing was trained.

Deliberately obscured code

The wider project studies how models read code that has been made hard to read on purpose. Every program appears at five tiers, from the original through meaningless renaming, control-flow scrambling, and all of it at once. One tier matters most here: the decoy, where identifiers are renamed to misleading ones, so the code does one thing while its names claim another. It is a Stroop test made of source code.

What we already knew

Two earlier results set this up. First, faithfulness does not predict whether the model gets the answer right — we tested that and refuted it (p = .93). The apparent effect was length: wrong reasoning runs about 1.6× longer, and faithfulness rises with how much the verbalizer had to say.

Second, faithfulness behaves like a describability meter. Meaningless renames read worst; real function names read best. And strikingly, misleading names read exactly as well as honest ones — 0.879 against 0.878. A decoy supplies meaning that is wrong but perfectly describable.

2 · Why “was it right?” cannot answer this

Faithfulness failing to predict correctness does not settle whether it detects confusion, because “wrong” conceals two opposite internal states.

Both bottom cells score as failures. A metric that merely tracks correctness can never separate them; a metric that tracks torn-ness would. And nothing in the project could see this distinction, for a mundane reason: every stored run was a single deterministic generation. One sample cannot tell you whether the model would have said the same thing ten times. The missing axis had to be built.

3 · What we built

Four stages, run back to back, unattended, on one GPU.

01

A measure of torn-ness

Sample eight answers per problem at a temperature that permits variation, for all 330 problems, then measure the disagreement between them. An item where all eight agree scores zero; an item producing eight different answers scores one.

The prompt builder and answer grader were imported unchanged from the original capture code rather than rewritten — rewriting them cost four bugs in an earlier experiment. As a check, we regenerated the deterministic answers and confirmed they reproduced the stored ones exactly: 8 of 8.

02

Recovering a signal we had never tested

The magnitude of the state vector is the most obvious alternative to faithfulness, and the project had never tested it against anything — purely by accident, because it had only ever been stored on data with no correctness labels. One forward pass per case recovered it at all 5,090 stored positions.

Each stored reading had recorded the exact token it came from, so we could verify that re-extraction still landed on that token: 5,090 of 5,090, none dropped, no outliers.

03

Read instability — the real candidate

This is the measurement whose construction matches the phenomenon, and the one we expected to work. Faithfulness asks whether one sentence carried the vector. Instability asks whether the vector has one sentence:

Describe the same vector five separate times, and measure how much the five descriptions disagree.

A state holding one interpretation should describe consistently. A state holding two incompatible interpretations should not. Agreement is measured by mapping each sentence back into vector space, so paraphrases count as agreement rather than disagreement — and a plain word-overlap score runs alongside it, because an earlier attempt to use an AI judge failed badly.

We sampled 400 positions, 2,000 readings. Two comparisons carry the argument. Function names in clean code are the most describable thing in the corpus, so they set the floor: if they wobble as much as everything else, we are measuring randomness in the describer, not the model. And decoy names against meaningless names — identical in shape, differing only in whether the name asserts a confident wrong meaning — separates the two ways instability can arise: two readings present, or none.

04

The comparison

Does any internal signal explain answer instability beyond the length of the reasoning? Length is the yardstick because length is what dismantled the earlier result. And separately: do torn and confidently-wrong items — matched for length — differ on any metric at all?

4 · Results

The decoy does not make the model torn

Misleading identifiers produce no more answer instability than the untouched original: −0.011, 95% interval [−0.098, +0.071] across 54 length-matched pairs. An interim look at 19 pairs suggested a strong positive effect, and it reversed once the data were complete.

Length alone explains 34% of the variation in answer instability. Every internal signal competes for the remaining couple of percent, and none of them wins it.

The reason: we measured the same thing twice

Sorting the six kinds of token by how unstable their readings are produces almost exactly the same order as sorting them by faithfulness — inverted.

Read instability is not a new instrument. It is describability, measured a second way. A state that is hard to describe also gets described inconsistently. That single fact accounts for everything else we saw:

  • The floor check passes — decoy tokens really are less stable than function names. So the measurement works. It simply discriminates describability, not ambiguity.
  • The decisive comparison is empty — decoy names against meaningless names comes out at −0.002, interval [−0.006, +0.003]. If anything, meaningless names are the less stable ones.
  • A decoy is not a second reading. It supplies one confident wrong meaning — exactly what the earlier 0.879-against-0.878 result implied.

What instability actually looks like

The steadiest reading in the corpus sits on a function name. Five independent descriptions:

Five different sentences, one consistent meaning. Now the least steady reading, which sits on a run of whitespace:

Token: whitespace — five descriptions
1 · “… Python DataFrame state transitions …”
2 · “… an FSM state machine in a TDD context …”

All five agree on the form — structured Python with numbered steps — and invent a different subject each time. That is not a model torn between two readings of the code. That is a describer confabulating because the state gave it nothing to say. Instability marks emptiness, not conflict.

The one thing that did work

How often the model changes its answer predicts whether it is right, at AUC 0.869 — mean instability 0.668 when wrong against 0.240 when right. This is the known self-consistency effect, and it fell out as a by-product. It is a better correctness signal than anything the interpretability instrument provides.

Worth noting too: confident wrongness is rare. Only 6 of 107 wrong items gave the same answer all eight times, against 83 of 223 correct ones. On this material, being wrong and being unstable nearly coincide.

5 · Two errors we caught

While pulling examples for this write-up, two of the three “confidently wrong” items turned out to be scoring artifacts rather than model behaviour. In one, the answers **[] and [] were counted as different — markdown bold splitting a single answer in two. In another, two dictionaries with identical contents in different key order were counted as different.

The comparator stripped spaces and quotes but not emphasis markers. 36% of items contained one somewhere. This is not cosmetic: answer instability is the outcome variable, and inflating it adds noise — and noise in an outcome weakens associations. A null could have been an artifact of the label rather than a fact about the model. We re-ran everything with a hardened comparator.

The one borderline positive did not survive. Read instability’s edge over length went from p = .029 to .234, while the behavioural finding got stronger. Both movements are diagnostic: removing label noise should push a spurious result toward nothing and a real one further from it. Every number in this report is the corrected one.

We also caught a statistical error that would have made a false positive the headline. Each signal was originally judged by resampling its gain in explained variance and asking whether the interval excluded zero. But that gain cannot be negative — adding any column to a regression never lowers the fit — so the interval excludes zero almost regardless of the data. On synthetic data with three predictors we knew to be pure noise, all three came back “significant.” Replaced with a shuffle test, the same data gave p = .51–.58.

6 · What it means

On the original question: faithfulness cannot signal confusion. Neither can the state’s magnitude, nor read instability. Not because the measurements were poor, but because all three are measuring describability, which is dominated by length. Faithfulness is not lower on code the model finds confusing — it is lower where there is less to say.

On the instrument: this is a sharper account of what faithfulness is than we had before, and it survived a test built to break it.

On the trap: misleading names make the model wrong, not torn. They do not install a competing interpretation it wavers between; they install a confident wrong one.

Limits

  • One model, one layer, one temperature setting. Torn-ness could be real but not linearly readable at this layer, in which case a single number per position was never going to find it.
  • Read instability averages under two positions per problem, so the per-problem term is underpowered; the per-reading comparisons are the well-supported ones.
  • Exploratory throughout, not pre-registered. Nothing here claims statistical significance — the nulls are informative, not proof of absence.

Next

  1. Sweep the layers. The cheapest remaining test of the “not readable at this depth” explanation.
  2. Induce torn-ness properly. Misleading names demonstrably do not. A real test needs genuinely ambiguous programs with two defensible answers — a stimulus-design problem, not a measurement one.
  3. Treat answer instability as the bar. At AUC 0.869 it beats every internal signal here. Any future claim that an internal measurement is useful has to clear it.
